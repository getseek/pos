# Premium POS documentation working rules

Read `README.md`, the approved dated plan in `plans/`, `maintenance/restaurant-comparison.md`, `maintenance/findings.md`, and the current completion report before changing this project.

- Work only in this standalone documentation repository. `F:\Premium_POS` and `F:\rust_restaurant` are read-only reference inputs. Never run application builds/tests that write into those trees or operate real shop data.
- The current authorized implementation ends at D02. Do not create public DNS/tunnels, change Caddy/cloudflared runtime configuration, register startup tasks, or operate any Restaurant process, port, task, environment or output directory.
- The approved ports are 18180 (future Caddy origin), 18181 (local preview), 18182 (future Caddy admin), and 18183 (future tunnel metrics). Preview binds only 127.0.0.1:18181.
- Machine-readable source-of-truth records are under `maintenance/`: `features.json`, `evidence-register.json`, `document-register.json`, `assets.json`, `content-inventory.json` and `source-inventory.json`. Derived public reference pages are generated by `scripts/render_registry.py`; do not edit them directly.
- Distinguish located code, inspected source, historical automated evidence, fresh checks, manual checks, physical-device checks and owner approval. Never infer whole-feature acceptance from a file, screenshot, migration number or test total.
- All public Markdown pages need stable IDs, review dates, DRAFT/REVIEWED/HISTORICAL maturity, register rows and explicit navigation. Approval is a separate owner action; document maturity does not imply product verification.
- Publishable assets need a review/classification record and digest. Keep raw audits, logs, TRX, private findings and credentials outside `docs/`. Never add symlinks/junctions or runtime imports from the application tree.
- Run `scripts/Build-Docs.ps1`, `scripts/Validate-Docs.ps1` and `scripts/Test-Docs.ps1` before a local documentation commit. The build stages and validates generated output before replacing the previous local artifact.
- No Git remote/push or automated public deployment has been configured. Preserve the original approved plan as dated history; record execution differences in maintenance reports.
